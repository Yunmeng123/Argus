# Argus Code

以最小、安全、可验证的变更完成任务。

## 编码前检查

开始编码前，必须先阅读并理解：

1. 目标文件；
2. 目标代码的直接调用者；
3. 相关接口契约，包括公开方法、HTTP API、事件或数据格式；
4. 影响行为的配置；
5. 现有相关测试。

随后列出完成任务所需的最小变更范围，包括计划修改的文件和不应改动的边界；未完成上述检查和范围说明前不得编码。

## Java

- 使用 Java 17，遵循仓库现有 Spring Boot 约定。
- 使用构造器注入，不使用字段注入。
- 优先使用不可变对象；适合纯数据载体时优先使用 `record` 或不可变 DTO。
- 避免无语义的 `null`；用明确的空集合、类型、校验或领域状态表达缺失值。
- 不得静默吞掉异常。保留原因并传播、转换为有语义的异常，或在适当层级记录和处理。
- 日志不得包含密钥、令牌、凭据、完整敏感请求或响应报文；只记录完成诊断所需的脱敏信息。

## 外部 HTTP 调用

- 复用统一的客户端创建和配置入口，不得在业务代码中临时创建配置各异的客户端。
- 明确配置连接超时和读取超时。
- 将鉴权封装在客户端、拦截器或专用组件中，不得散落在业务逻辑中。
- 按成功、客户端错误、鉴权错误、限流和服务端错误等类别处理状态码，并保留可诊断上下文。
- 仅对明确可重试且幂等的失败执行有限次数重试；使用退避策略，禁止无限重试。
- 通过接口、工厂或依赖注入使 HTTP 客户端可替换，以便测试使用 stub 客户端且不访问真实外部系统。

## 并发与异步

涉及并发、队列、事件或异步任务时，在实现说明和测试中明确：

- 幂等键的来源、作用域和有效期；
- 重复投递时是忽略、合并、覆盖、重试还是返回既有结果；
- 任务取消和任务合并的语义，包括竞态时的行为；
- 线程池、流、连接、订阅等资源的所有权与关闭方式；
- 部分失败、进程重启、超时或中断后的恢复策略。

不得用未说明的默认行为代替这些决策。

## Vue

- 将所有后端请求集中在 `web/src/api/`，页面和组件不得直接调用 HTTP 客户端。
- 页面必须明确处理 `loading`、`error` 和 `empty` 状态，不得只实现成功路径。
- 优先复用已有组件、布局模式和 CSS 变量；不要引入重复组件、硬编码主题值或平行样式体系。

## 测试与验证

- 修复缺陷时先增加能复现缺陷且在修复前失败的回归用例，再实施修复。
- 外部系统必须使用 stub 或可控的测试替身，不得在单元测试中调用真实服务。
- 异步测试使用可等待的信号、future、虚拟时间或轮询断言，不得依赖任意时长的 `sleep`。
- 覆盖正常路径、关键边界和变更引入的失败路径。
- 变更后至少执行相关单元测试和对应构建；如因环境限制无法执行，明确记录未执行项和原因。

## Git 与变更卫生

- 每个提交只包含一个目的，提交信息准确描述该目的。
- 禁止修改或提交 `web/node_modules/`、`target/`、`data/` 和生成的静态资源。
- 禁止夹带全仓格式化、无关重命名、依赖升级或顺手清理。
- 提交前检查 diff 和 Git 状态，确保仅包含已声明的最小变更。

## 停止条件

发现以下任一情况时，立即停止修改并请求用户确认：

- 需求存在会影响实现选择的歧义；
- 需要改变跨模块契约；
- 需要数据库迁移；
- 会破坏公开 API；
- 变更范围明显超出已声明的最小范围。
